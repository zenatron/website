A self-hosted tracker, timer and rewards manager for key-based commitment
training. Honour system and photo verification — no device integration, no
hardware in the loop.

<Callout type="note" title="The design constraint">
The lock is a social commitment device, not a cryptographic one. The app's job is
to make a commitment feel real, track it honestly and reward it — while never
being able to stand between a person and physically ending it. Emergency release
is available at every strictness tier, always.
</Callout>

That constraint is the interesting part of the build. Software that enforces
nothing has to earn its authority some other way, which pushes all the design
weight onto the record: if the log can be quietly edited, none of it means
anything.

## How the record works

- **An append-only points ledger.** Entries are added, never mutated. Balance is
  a fold over history rather than a number someone can set.
- **Timers derived from timestamps**, not from a counter that ticks. Restarting
  the app, or the server, changes nothing about elapsed time.
- **Photo verification into private buckets** on MinIO, served through
  pre-signed URLs with EXIF stripped on upload — so a verification photo can't
  quietly carry a location with it.

## Stack

SvelteKit on `adapter-node`, TypeScript end to end, Postgres with Drizzle,
MinIO for object storage, and Pocket ID or any OIDC provider over Authorization
Code with PKCE. Tailwind 4, shipped as a dark-first PWA with an offline shell and
web push.
